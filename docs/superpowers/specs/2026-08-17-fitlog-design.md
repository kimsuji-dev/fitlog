# fitlog — 개인 운동 기록 PWA 설계

2026-08-17. Fleek 무료버전의 기록 제한을 대체하는 1인용 운동 기록 앱.
사용자 폰: 갤럭시(Android). 캘린더는 남편과 공유됨 → 민감 정보 분리가 요구사항.

## 전체 구조

서버 없는 순수 클라이언트 PWA.

```
[PWA (폰 Chrome, 홈 화면 설치)]
 ├─ IndexedDB: 모든 데이터 원본 저장 (운동, 몸무게, 식단 평가)
 └─ Google Calendar API 직접 호출: 운동 저장 시 이벤트 즉시 생성/갱신

[맥미니 (24시간 가동)]
 └─ launchd 2주 주기: tg "몸무게 재셔야 하는 날이에요! ⚖️"
```

- 스택: React + Vite, 정적 호스팅(GitHub Pages)
- 맥미니에 서버 코드 없음. 알림은 기존 `tg`(텔레그램) 명령 + launchd 스케줄 한 줄
- 캘린더 인증: Google Identity Services 토큰 클라이언트 (브라우저에서 직접)

## 데이터 모델 (IndexedDB)

- **운동 종목**: 이름, MET 계수, 종류(웨이트/유산소). 기본 목록 내장 + 사용자 추가 무제한
- **운동 세션**: 날짜, 시작/종료 시각, 종목별 기록(웨이트: 세트×횟수×무게, 유산소: 거리/시간), 메모, 캘린더 이벤트 ID
- **몸무게 기록**: 날짜 + kg. 잴 때마다 한 건씩 쌓임
- **식단 평가**: 날짜 + 3단계 (🥗 잘 먹음 / 😐 보통 / 🐷 만땅)
- **프로필**: 키(1회 입력)

## 자동 계산

- **칼로리** = Σ(종목별 MET × 최신 몸무게kg × 시간h). 추정치임을 화면에 표시
- **난이도 별점(1~5)** = 그날 총 볼륨(세트×횟수×무게 합)을 최근 4주 평균 대비 상대 등급.
  기록이 쌓이기 전에는 칼로리 기준 임시 산출

## 캘린더 이벤트 (운동 저장 즉시 생성, 같은 날 수정 시 갱신)

```
제목: 💪 운동 ★★★☆☆ (~420kcal) 🥗
시간: 18:00–19:10
설명:
- 벤치프레스 3세트 ×10 ×60kg
- 스쿼트 3세트 ×10 ×80kg
- 러닝 20분 3km
메모: 컨디션 좋음
```

- 식단 평가는 제목 끝 이모지로만 포함. 운동 안 한 날의 식단 평가는 캘린더에 안 올라감
- **키·몸무게는 어떤 형태로도 캘린더에 올라가지 않는다** (남편과 공유되는 캘린더)

## 화면 (3개)

1. **오늘 기록**: 운동 시작 → 종목 선택·세트 입력 → 종료 시 캘린더 업로드. 식단 평가 3버튼 포함
2. **이력**: 날짜별 운동 목록, 종목별 최근 기록(지난 무게 참고), 몸무게 추이 라인 그래프
3. **설정**: 키 입력, 몸무게 입력(잴 때마다), Google 계정 연결, JSON 내보내기

## 몸무게 알림

- 맥미니 launchd, 고정 격주 스케줄(예: 격주 월요일 오전 9시)로 `tg "몸무게 재셔야 하는 날이에요! ⚖️"` 실행
- ponytail: 고정 격주 스케줄이라 최근 측정일과 무관하게 알림이 옴. "마지막 측정일 기준 14일"이 필요해지면 맥미니에 소형 서버 추가

## 에러 처리

- 캘린더 업로드 실패(오프라인, 토큰 만료): 기록은 항상 로컬에 먼저 저장, 업로드는 미전송 표시 후 다음 접속 시 재시도. 데이터 유실 없음
- Google 토큰 만료 시 재로그인 팝업이 가끔 뜸 — 서버 없는 구조의 트레이드오프

## 테스트

- 칼로리·별점 계산, 캘린더 이벤트 본문 생성(제목/설명 포맷)에 대해 소형 단위 테스트
- 캘린더 API 연동은 실제 계정으로 수동 확인
